# Google data review — Round 6

Reviewed 15 November 2026 (Pacific time), using Google's current official documentation and standard non-EEA terms. Billing address determines which agreement applies; EEA terms differ. No paid requests, API keys, account changes, or extraction from the Google Maps interface were used for this review. Context7 was also consulted for the official JavaScript Elevation response contract.

**Recommendation: keep open elevation and map data as Wordscape's recording foundation.** Google's services can supply excellent live visual context, but their published standard permissions do not fit a portable, editable world file containing extracted Google terrain or buildings. A Google visualization mode would be a separate product choice, not an accuracy upgrade to the exported document.

**Storage and export are the deciding constraints.** The general terms restrict scraping, caching, creating derived content, and combining content with non-Google maps unless an applicable exception permits it. Attribution alone does not grant redistribution rights. Saving an Elevation grid inside `.wordscape.json`, deriving building geometry from Google imagery/tiles, or sending those tiles to an extraction model would conflict with these published restrictions. Any different arrangement would need express permissions covering the actual workflow. [Terms, §3.2.3](https://cloud.google.com/maps-platform/terms)

**A live Google backdrop is a narrower, documented option.** Google's tile policies expressly allow independently created 3D objects over Photorealistic 3D Tiles, provided those objects were not traced or derived from the tiles. Google content and its attribution must remain distinguishable from the application's own models. This does not turn the backdrop into exportable source data. We should not generalize that allowance into permission to blend Google's data into Wordscape's OSM map or stored terrain. [Overlay and attribution policies](https://developers.google.com/maps/documentation/tile/policies)

**Access would require setup and operating cost controls.** Elevation and Map Tiles require a Google Cloud project with billing enabled, an enabled API, and authentication. Billing is usage based; quota controls, restricted credentials, and current SKU pricing would need review before integration. A free usage allowance is not an open-data licence. This review does not assume an existing Google key or authorize charges. [Elevation billing](https://developers.google.com/maps/documentation/elevation/usage-and-billing), [3D Tiles setup](https://developers.google.com/maps/documentation/tile/3d-tiles)

Wordscape's useful distinction is an editable record: named objects, measured versus inferred facts, source trails, authored procedural geometry, and a document that can survive a change of renderer. Matching Google's global photorealistic viewer would consume effort without advancing those goals. For the remaining rounds, adjacent survey composition and the planned imaginary-world authoring flow are the stronger investments; photorealistic Google comparison can remain an external reference.

The current alternatives support the intended persistence model. USGS 3DEP products are free of use restrictions, with product-specific resolution and vertical datum retained in our evidence. OpenStreetMap permits copying and adapting its database under ODbL, including attribution and applicable share-alike obligations; it is not public domain. Coverage gaps and inferred heights still need explicit labels. Neither source guarantees complete buildings, entrances, or trees. [USGS products and services](https://www.usgs.gov/3d-elevation-program/about-3dep-products-services), [OSM copyright and licence](https://www.openstreetmap.org/copyright)

No Google integration was added in Round 6. Recheck the linked policies and the account's actual agreement if a future round proposes a live Google visualization mode.
